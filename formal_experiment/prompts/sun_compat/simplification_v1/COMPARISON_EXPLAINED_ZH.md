# 原版、A、B 的逐项通俗对照

本文按三个已保存 prompt 的实际差异解释，不改 prompt，不把设计动机当作已验证效果。
原版指 `direct_llm_sun_record_prompt_v6_d1r1_2026_08_05.md`。
J 指模型输出 JSON 的要求；S 指六类字段的含义、分类与抽取边界；E 指示例。

| 比较项 | 原版 v6 | A | B |
|---|---|---|---|
| JSON 输出要求 J | 展开的字段清单、固定值、禁止项与自检 | 压缩这些要求 | 与 A 相同 |
| 语义抽取规则 S | 原规则 | 原样保留 | 压缩、重组，并改变部分判定规则 |
| 示例 E | 六个 | 六个，原样保留 | 六个，原样保留 |
| System 字符数 | 6172 | 5676，少 8.0% | 4398，少 28.7% |

字符数只针对 System，不是含六个示例的完整请求，也不是 token 或费用下降比例。
A 的问题是：缩短输出指令后，结构合规和抽取表现怎样变化？
B 相对 A 的问题是：再加入语义规则重组、提示减少和分类/边界改动后怎样变化？
B 对原版的变化包含 A 的全部变化。

## A 相对原版：六项输出指令改动

| 改动 | 原版怎样写 | A 怎样写 | 为什么尝试、可能损失什么 |
|---|---|---|---|
| 1. 删除发送给模型的合同编号/长哈希宣告 | 要求遵守指定合同和 SHA-256 | 不在 System 中重复宣告 | 模型没有收到对应合同正文，只有编号/指纹；程序仍保存身份与哈希。不能据此认定长哈希有害。 |
| 2. 合并外围文本禁止项 | 单独禁止 Markdown、解释、评论、推理文本、前后附言 | 一个 JSON 对象、无额外字段和外围文本 | 都在表达“只输出对象”。仍禁止在 JSON 外写解释，没有新增解释输出；遵循率可能变化。 |
| 3. 删除八个顶层字段的显式清单 | 逐个列出 schema_version、sample_id、source_id、source_text、clauses、method、validation、unsupported_or_ambiguous | 字段名和类型按保留的示例 | 示例含相同结构，但从“文字明确列出”改成“参照示例”，可能漏键，不能称完全无损。 |
| 4. 合并固定值和输入回显 | schema_version/method 各项单列；三个输入字段原样复制 | 集中写在短 Output 段 | 固定值和原样复制要求没有删除。模型仍需输出这些字段，没有新加程序自动补字段。 |
| 5. 压缩 validation 说明 | 输出固定 validation，运行时验证器为权威 | 同样的固定对象，注明占位符、程序验证为权威 | 含义保留；模型写 true 仍不代表实际通过验证。 |
| 6. 缩短末尾自检 | 再提醒所有必需键、无额外键、固定枚举、精确跨度、引用和推断边界 | 检查结构、精确跨度、同句 ID 引用和只用原文证据 | 减少重复提醒，但删去的提醒也可能帮助模型；效果需要实测。 |

A 没有改变原版规则 9–19、25–27 的字段定义、关键词列表和抽取边界。
A 也没有取消 JSON、放开外部知识、让模型输出解释，或修改程序 schema/校验器。
其主要变化是 JSON 指令的表达压缩，字段清单改由示例承载是需要单列的风险。

## B 相对 A：语义部分的十二项变化

| 改动 | 原版/A | B | 通俗解释与风险 |
|---|---|---|---|
| 1. 模态 modality | 四类标签、最小触发词、必要否定证据 | 四类和证据要求保留，短写 | 主要是表述缩短；没有取消义务/禁止/许可/定义分类。 |
| 2. 执行者 actor | 主语代词、最小名词短语、代词和被动句分开讲 | 集中讲，并新增“动作宾语不是执行者” | 如公司提交报告，公司是执行者、报告是宾语。新增限定可能帮助角色区分，也可能在复杂句中过度排除；删除 it/they 显式举例，仍保留主语代词要求。 |
| 3. 动作 action 边界 | 动作含必要宾语；同时要求到条件/限制/例外短语开始处就结束 | 依据语法范围，不自动在触发词处截断；排除独立表达的限定内容 | 为减少过早截断和必要宾语缺失而尝试，属于判定规则变化。也可能使动作过长、吞入限定内容。 |
| 4. 条件 condition | 定义加 if/when/where/unless/provided that 等触发词清单 | 保留适用前提、标记和完整命题，删除这串提示词 | 由具体词提示转向功能定义。文字更短，但可能漏掉以前靠提示词识别的前提。 |
| 5. 限制 constraint 定义 | 两处讲功能和类别，明确 smallest complete limit | 合并为方式、数量、地点、时间、目的、排他性、法律引用；写 complete limit | 要求完整限制仍在，“最小”的明确要求弱化，可能抽得更长。 |
| 6. 限制提示词 | 列出时间、数量、目的、排他性及法律引用的典型词 | 保留功能类别及少量法律短语，删去大部分典型词 | 删除 within N/until/after/before/during、at least/at most/no more than、for the purpose of、only/solely/exclusively、in accordance with/as defined in 等提示；不是只删重复句，存在召回损失风险。 |
| 7. 例外 exception 和 unless | 例外定义含 removes or narrows；示例把排除型 unless 放例外，但条件词表也列 unless | 强调按功能分类，排除原本适用规则的 unless 是例外，不仅因关键词再放条件 | 为澄清原文规则与示例的歧义而尝试。不是“所有 unless 都是例外”；同时不再显式写 narrows，可能影响收窄情形。 |
| 8. 缺失和不确定 | 明确空数组表示缺失、不表示不确定 | 用 [] 表示缺失；有证据但不确定的 span 保留并标记 | 核心区别保留，但少了一次明确提醒，可能增加漏抽。 |
| 9. 不确定理由 | 四个允许的 reason 逐行列出，写 Use only | 相同四个值合为一段 | 值没改，格式和排他强调弱化；不能保证模型同样遵循。 |
| 10. 未解析代词 | 规则含 it 归一化小例子和一个理由 JSON 小例子 | 保留原文形式、不补先行词和 actor 理由，删除小例子 | 不会允许猜代词指谁，但更依赖六个完整示例中的第一个示例。 |
| 11. 被动句 | 无执行者不猜；明确提示 by-phrase 可提供执行者 | 无执行者不猜仍保留，移到 actor 段；删 by-phrase 表面形式提示 | “由谁做”仍要有原文证据；缺少 by 提示可能影响带明确施事者的被动句。 |
| 12. 定义、片段、字段分开和嵌套 | 分散在规则 19、26、27 | 集中讲，保留定义可无动作、片段可无分句、嵌套限制同时放 condition/constraint | 规则集中呈现，不意味着行为已证明等价；动作边界变化另见第 3 项。 |

例如 “The company must submit the report unless consent is withdrawn.”：
三个版本都要求只根据原文抽取；B 额外明确动作宾语不是 actor，并对排除型 unless
规定 exception 优先。原版/A 的示例已经展示例外用法，但条件词表仍列 unless。
这是说明判定差异的合成例子，不是模型实测输出。

三个版本均保留六个完整示例、用户模板、只用目标原文、精确坐标、禁止补充外部
先行词，以及分句、并列、关系和 ID 规则。程序后处理、Gold 与评价器没有随本说明
改变。A 不等于取消 J；B 不等于取消 S。当前没有候选实测结果，不能说任一版更好。

完整英文及中文翻译见 [PROMPT_BILINGUAL_REVIEW.md](PROMPT_BILINGUAL_REVIEW.md)。
